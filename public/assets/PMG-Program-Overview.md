# Mathsya — Proactive Mobility Guardian (PMG)
October 2026 | Vehicle software with optional cloud/SaaS | Architecture and PoC planning

## Product role
PMG joins selected module insight with vehicle, journey and customer context. Battery & Charging AI is a module software product; Evo Core is the power-hardware platform. PMG connects approved information from these products and other vehicle modules to permitted recommendations and verified outcomes. It can start with existing module data without replacing every module.

## Embedded vehicle runtime
Suitable gateway, telematics or central compute is selected for the reference architecture. The runtime combines module events with vehicle context, prepares reviewable recommendations, preserves focused history and verifies outcomes. Missing-data and offline behavior need a defined local response. Exact APIs, network, memory, latency and compute are established in the integration proof.

## Optional cloud/SaaS
Authorized vehicle evidence can support fleet comparisons, OEM quality investigations, service decisions and tracking of a correction. Cloud services need agreed access, consent, retention, security and ownership. SaaS describes this optional cloud delivery; vehicle software still requires embedded integration, validation and lifecycle support.

## Three candidate workflows
1. Charging readiness: battery context + departure intent → permitted charging/preconditioning guidance → verify readiness.
2. OEM quality: local behavior change + vehicle/version context → focused investigation evidence → verify an approved correction.
3. Incident context: existing authoritative incident trigger → preserve relevant before/after context → permitted handoff and acknowledgement.

## Benefits and measures
Customer: useful readiness, understandable health/thermal guidance and informed service planning.
OEM/fleet: comparable evidence, less repeated triage and a measurable quality/service learning loop.
Measure readiness, false alerts, recommendation acceptance, evidence completeness, investigation time, recurrence and attributable cost. Compare with existing diagnostics and workflows.

## First proof
A proposed 12–16 week PMG software PoC begins after a partner, approved data and test access are agreed: define baseline (weeks 0–2), connect runtime (2–6), evaluate controlled workflows (6–10), and decide the paid next program (10–16). Battery AI model development and Evo Core hardware need separately scoped paths.

## Authority and commercial path
Validated control and safety functions retain their authority. Available interfaces and customer permissions govern recommendations/action requests.
Proposed revenue: paid integration, embedded licensing/support and optional enterprise subscriptions/services after recurring buyer value is proven. No achieved performance, signed contracts or released pricing is claimed.
