SOFTWARE DELIVERY / COMMERCIAL OPTIONS
## Inside the vehicle.
 Beyond it, where useful.
PMG’s embedded runtime and its optional cloud services have different responsibilities and different routes to revenue.
 ON THE VEHICLE / SOFTWARE
### PMG edge runtime
Runs on suitable vehicle compute, such as a gateway, telematics unit or central computer, as selected for the reference architecture.
- Combine module events with vehicle and journey context.
- Prepare reviewable recommendations and permitted action requests.
- Preserve focused history and verify the result locally.
- Define behavior for missing data and lost connectivity.
 PROPOSED COMMERCIAL PATH
Program integration + embedded-software licensing and support.
 OFF THE VEHICLE / OPTIONAL SaaS
### OEM & fleet learning services
Authorized vehicle evidence can support cross-vehicle comparison and organization-level workflows.
- Compare relevant events across permitted vehicles and versions.
- Support quality investigations and service decisions.
- Track whether a correction reduced the repeat behavior.
- Manage access, consent, retention and data ownership.
 PROPOSED COMMERCIAL PATH
Enterprise subscription or service terms after buyer value is validated.
SaaS describes the optional cloud offering. Local vehicle software still needs embedded integration, validation and lifecycle support.

QUESTIONS ABOUT PMG
## A platform direction.
 A scoped first proof.
Is PMG a hardware product?
PMG is a software product direction. It runs on suitable vehicle compute and can connect to optional cloud services. Evo Core is the portfolio’s EV power-hardware platform; Battery & Charging AI is a module software product.
Does PMG control everything in the car?
No. The selected architecture defines available interfaces and permitted requests. Validated control, protection and safety functions retain their authority; PMG coordinates context and evaluates outcomes within the approved scope.
What makes this different from today’s diagnostics?
The intended addition is a connected evidence loop: local behavioral insight, vehicle and customer context, a permitted response and verification after the response. The pilot must show an incremental advantage over existing diagnostics and service workflows.
What is the first adoption path?
Choose one valuable vehicle workflow with an OEM, supplier or fleet partner. Agree signals, the baseline, integration responsibility, customer permissions and acceptance criteria before expanding the scope.
